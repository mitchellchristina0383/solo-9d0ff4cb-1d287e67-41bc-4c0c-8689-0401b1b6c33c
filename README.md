# 日志检索值班台

FastAPI + SQLite（FTS5）实现的日志录入、检索与**阈值告警**服务，支持**不中断服务的在线索引重建**。前端为单页页面，Docker Compose 一键启动。

## 启动

```bash
docker compose up --build
```

浏览器打开 <http://localhost:8000>（可用 `PORT` 环境变量改端口）。数据保存在命名卷 `logdata` 的 `/data/logs.db`。

本地开发（Python 3.11+，SQLite 需带 FTS5）：

```bash
pip install -r requirements-dev.txt
uvicorn app.main:app --reload
# 测试
pytest
```

## 功能与接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/` | 网页（告警 / 规则 / 录入 / 检索 / 重建状态） |
| POST | `/api/logs` | 录入 `{“service”: ..., “body”: ...}` |
| GET | `/api/logs?q=&service=&limit=&offset=` | 关键词 + 服务名检索（两者 AND） |
| GET | `/api/services` | 已有服务名及数量 |
| POST | `/api/rules` | 登记告警规则 `{“service”, “keyword”, “window_seconds”, “threshold”}`（201；该服务已有规则时 409，关键词无法匹配时 400） |
| GET | `/api/rules` | 列出全部告警规则 |
| DELETE | `/api/rules/{id}` | 删除规则（204；不存在时 404）。已开的告警保留 |
| GET | `/api/alerts?status=open\|ack\|all&limit=&offset=` | 列出告警（默认只看未确认） |
| POST | `/api/alerts/{id}/ack` | 确认告警（200；不存在 404，已确认 409） |
| POST | `/api/reindex` | 发起后台重建（202；已有重建时 409） |
| GET | `/api/status` | 当前索引、重建进度、未确认告警数、最近一次重建结果 |
| GET | `/healthz` | 健康检查 |

检索关键字支持中文与英文：英文按词前缀匹配（`timeout` 可命中 `timeouts`），中文按字及相邻两字组合建立倒排，因此 `登录`、`登录失败` 均可命中。关键字为空时只按服务名列出。

## 告警语义

- 每个服务登记**一条**规则：关键词、窗口秒数、触发条数。关键词匹配沿用检索的同一套规则（对刚写入的日志在生效索引上做 FTS MATCH）。
- 规则只统计**登记之后提交**的日志：登记事务内快照 `start_log_id = MAX(logs.id)`，与日志写入由同一把写锁串行化，因此”规则登记与日志录入交错”只取决于谁先提交。
- 命中按**非重叠窗口**统计：以首条命中时间为起点开窗 `[起点, 起点+窗口秒数)`，窗口外的下一条命中另开新窗。
- 窗口内命中数达到门槛时**只开一条**告警（`alerts.window_id` 唯一约束兜底）；之后同窗口的命中继续计数但不再开单。
- 值班员在网页确认告警。确认**不会**重置窗口：同窗口的新日志不再开单，只有**下一个窗口**再次达到门槛才开新单。确认按提交状态判定，重复确认返回 409。
- 日志行、FTS 索引行、窗口/告警更新在**同一个 `BEGIN IMMEDIATE` 事务**中提交，任一步失败整体回滚，不会留下”有日志无索引”或”有告警无日志”的单边结果。
- 索引重建只把日志复制进新 FTS 表，**不重新评估规则**，因此重建不会重复开单；重建期间的写入照常评估告警。

## 重建设计

- 每次重建生成一个独立的 FTS5 表（`index_generations.fts_table`），旧索引在重建期间继续对外服务。
- 重建开始时记录快照上界 `start_id`。后台线程分批把快照内日志写入新表（`build_cursor` 单调推进）。
- 重建期间的写入在**同一个事务**里同时写日志表、当前生效索引和新索引，因此新索引天然包含”重建开始后提交”的日志。
- 启用前在一个 `BEGIN IMMEDIATE` 事务内校验新表行数等于日志总数，然后原子切换 `active` / `retired`；读者在一个读事务里先取当前 generation id，再查询该 generation 的表，一次检索不会混用新旧索引。
- 启用后旧索引表保留（`retired`），保证已开始、尚未结束的检索不受影响；新进程启动时清理历史表。
- 重建失败或进程重启：`building` 记录标记为 `failed` 并丢弃半成品表，原 `active` 索引不受影响，可直接重新发起。

## 已知限制

- 单进程部署：重建任务是在进程内线程，`docker compose` 使用单个 uvicorn 进程，不可横向扩到多个 worker/副本共享同一个 SQLite。
- 检索为 AND 语义，不支持 OR / 短语 / 模糊纠错；中文按二元字组匹配，没有分词词典。
- 索引表越来越多时只在新进程启动时清理 retired 表，运行期间保留。
- 日志正文没有单独截断/脱敏，写满磁盘等极端故障未做专门处理。
- 告警只在写入路径上同步评估，没有通知外发（邮件/Webhook）；窗口与告警表只增不删，长期运行需自行清理历史数据。
- 窗口按日志写入时间（秒级）划分，不处理乱序到达的历史日志。
